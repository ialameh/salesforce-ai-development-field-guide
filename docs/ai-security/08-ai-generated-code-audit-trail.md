# S8. AI-Generated Code Audit Trail

When code is generated by an AI tool, the organization must be able to answer: what was generated, by whom, for which org, when, and what review happened before deployment. This is both a compliance requirement (SOC 2, HIPAA, GDPR) and an operational necessity. Code without a traceable origin is a liability. This chapter covers how to build and maintain an audit trail for AI-generated Salesforce code.

## Why audit trails matter for AI code

Human-written code has natural provenance: the author, the commit, the PR review, the deploy. AI-generated code lacks this provenance unless you build it. When an AI-generated class causes a production failure, you need to be able to answer what was generated, by which AI tool, at what time, in what context, and who reviewed it before it reached production.

Without this audit trail:
- Production failures from AI code cannot be root-caused effectively
- Compliance auditors cannot verify that AI code went through the required review
- The organization cannot demonstrate that AI tools are being used responsibly
- Incident retropectives lack the context to understand what happened

## What the audit trail must capture

For each AI-generated file:

```
Audit record fields:
- File name and path
- AI tool used (Claude Code, Copilot, Cursor, etc.)
- AI model used (if available from the tool)
- Date and time generated
- Prompt used (or prompt template reference)
- Developer who initiated the generation
- Scratch org or sandbox used during development
- Reviewer who approved deployment
- Date of review approval
- Target org for deployment
- CI/CD pipeline run (if deployed via pipeline)
```

The audit record should be stored in a way that is accessible, tamper-resistant, and tied to the code itself. The simplest approach: a comment header in the generated file that captures metadata, plus a separate log for organizations that need formal audit trails.

## File-level audit headers

Add a header comment to each AI-generated file:

```apex
/**
 * AI-Generated Code Audit Header
 * Generated by: Claude (Anthropic)
 * Model: Claude 4 Sonnet
 * Date: 2026-05-05
 * Developer: jsmith
 * Reviewer: abrown
 * Review Date: 2026-05-05
 * Review Tool: reviewer-AI (sf-code-review skill, 13 lenses)
 * Deployment Target: ai-dev-scratch
 *
 * Prompt Reference: [brief description of what was requested]
 * Multi-Agent Workflow: architect-AI -> developer-AI -> reviewer-AI -> security-AI
 *
 * This file has been reviewed and approved for deployment.
 */
```

The review tool and multi-agent workflow fields capture the review process that happened before human sign-off.

## Log-based audit trails

For formal compliance needs, maintain a separate audit log:

```json
{
  "file": "force-app/main/default/classes/OpportunityService.cls",
  "generatedAt": "2026-05-05T14:23:00Z",
  "aiTool": "Claude Code",
  "aiModel": "claude-opus-4-7",
  "developer": "jsmith",
  "orgUsed": "ai-dev-scratch",
  "reviewProcess": {
    "reviewerAI": {
      "tool": "reviewer-AI",
      "result": "Passed with 2 findings (fixed)",
      "date": "2026-05-05T14:45:00Z"
    },
    "securityAI": {
      "tool": "security-AI",
      "result": "No critical findings",
      "date": "2026-05-05T14:50:00Z"
    },
    "humanReview": {
      "reviewer": "abrown",
      "date": "2026-05-05T15:00:00Z",
      "approved": true
    }
  },
  "deployment": {
    "targetOrg": "ai-dev-scratch",
    "date": "2026-05-05T15:30:00Z",
    "ciRunId": "github-actions-run-12345"
  }
}
```

Store this log in a durable location (GitHub Actions artifact, custom object in the org, or a dedicated audit system).

## Git history and AI-generated code

Git history is part of the audit trail. AI-generated code commits should be identifiable:

```
Git commit message convention for AI-generated code:
feat: Add OpportunityService (AI-generated)
- Generated by: Claude Code
- Reviewed by: abrown
- PR: #123

This commit adds OpportunityService.cls which was generated with AI assistance.
The code has been reviewed by reviewer-AI and security-AI before human review.
```

This makes it visible in git log and git blame that a file was AI-generated. This is useful for auditors and for the team reviewing changes in PRs.

Do not hide AI origins. The AI attribution is in the commit message and file header, not hidden. This is transparency, not a problem.

## CI/CD pipeline audit records

When AI-generated code is deployed via CI/CD:

```
Pipeline audit record (automatically captured):
- Pipeline run ID
- Commit SHA
- Files changed
- Test results
- Who approved the deployment (for manual approval gates)
- Target org
- Deploy command used
- Pass/fail status

This data is captured by the CI/CD system automatically. Ensure the pipeline configuration captures the right data and retains it.
```

GitHub Actions provides this via the workflow run history. Other CI systems have similar capabilities.

## When AI generates partial code

AI often generates partial code (a single method, a trigger handler addition) rather than a full file. The audit trail must cover partial changes as well:

```
Partial AI generation audit:
- File modified: OpportunityTriggerHandler.cls
- Lines changed: 45-78 (new method handleClosedWon)
- AI tool: Claude Code
- Developer: jsmith
- Review: Same process as full-file generation

Use structured commit messages:
feat: Add handleClosedWon method (AI-generated)
- AI-Generated Addition: OpportunityTriggerHandler.handleClosedWon()
- Reviewed by: abrown
```
